# Spectral Characteristics (calc_sp_ch)

Плагин QGIS, который измеряет, насколько каждый векторный объект похож на
спектральную сигнатуру своего класса на космическом снимке.

Он отбирает пиксели растра внутри каждого полигона, сводит их в спектральные
характеристики, строит эталонный профиль для каждого класса и оценивает каждый
объект по эталону его собственного класса. Итог — **типичность**: 1 (типичный),
2 (сомнительный) или 3 (нетипичный). Оценки хранятся в проекте и выгружаются в
JSON и CSV.

Documentation in English: [README.md](README.md)

---

## Зачем это нужно

Обычная задача — проверка карты по снимку: выделы, участки, водоёмы или поля уже
оконтурены и классифицированы, и нужно понять, какие из них действительно
выглядят на снимке как их класс. Объекты, оказавшиеся нетипичными, — это как раз
те, которые стоит пересмотреть: вырубленный выдел, участок со сменившимся
использованием, полигон, нарисованный не там.

В отличие от классификации плагин не назначает классы. Он берёт класс, который у
вас уже есть, и спрашивает, насколько тот правдоподобен.

## Требования

- QGIS 3.22 или новее (разработка и проверка — на 3.44 LTR)
- `numpy` — входит в любую сборку QGIS
- `matplotlib` — есть в сборках OSGeo4W/Windows и macOS, но не во всех пакетах
  Linux-дистрибутивов. Без него плагин всё равно загружается, и работает всё,
  кроме графиков, — об этом написано прямо в области графика. В Debian/Ubuntu:
  `sudo apt install python3-matplotlib`.

Векторный слой и растр могут быть в разных системах координат: геометрия
переводится в CRS растра перед выборкой. Ошибка перепроекции не проглатывается,
а показывается.

## Установка

**Из ZIP.** Скачайте архив репозитория, затем в QGIS:
*Модули → Управление модулями → Установить из ZIP*.

**Из исходников.** Склонируйте репозиторий в каталог модулей QGIS так, чтобы
папка называлась `calc_sp_ch`:

```bash
git clone https://github.com/bes-leak/calc_sp_ch.git
```

| Система | Каталог модулей |
|---|---|
| Windows | `%APPDATA%\QGIS\QGIS3\profiles\default\python\plugins` |
| Linux | `~/.local/share/QGIS/QGIS3/profiles/default/python/plugins` |
| macOS | `~/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins` |

Затем включите *Spectral Characteristics* в менеджере модулей. Панель
открывается кнопкой на панели инструментов или через *Вектор → Spectral
Characteristics*.

## Быстрый старт

1. Загрузите растр и векторный слой, сделайте векторный слой активным.
2. Откройте панель плагина. Выберите растр в верхнем списке: в нём только
   **видимые** растровые слои, в порядке дерева слоёв.
3. В поле **class:** выберите атрибут с классом объекта (например `type_name`).
   Если слой уже стилизован категоризованным рендерером, поле подхватится из
   стиля само.
4. В поле **key:** выберите устойчивое поле-идентификатор. По умолчанию ключом
   служит fid, но он меняется при пересохранении слоя, а настоящее поле-
   идентификатор это переживает. Значения должны быть уникальными.
5. Выделите на карте объекты одного класса и нажмите **★**. Так строится эталон
   класса: средний спектр, ковариация и гистограммы каналов. Повторите для
   каждого класса.
6. Выделите один объект и нажмите **⚙ Auto-assess**, чтобы увидеть весь расчёт,
   или **⚙ Batch over layer**, чтобы оценить сразу весь слой.
7. Нажмите **💾 JSON** для выгрузки или **▦ Separability matrix**, чтобы сначала
   проверить, насколько классы вообще отличимы друг от друга.

## Элементы панели

| Элемент | Что делает |
|---|---|
| список растров | растр, с которого читаются спектры; только видимые слои |
| `polygon` / `bbox` | брать пиксели внутри контура или весь его охват |
| `bar` / `line` / `step` | вид графика распределения |
| 🔍 Analyse | построить спектр выделенного объекта |
| 💾 JSON | выгрузить характеристики объектов (см. ниже) |
| **profile:** | библиотека эталонов классов, лежащая в проекте |
| ★ | построить или обновить эталон по выделенным объектам |
| 💾 / 📂 | сохранить эталоны в файл, загрузить обратно |
| ↻ | пересчитать все эталоны по выбранному сейчас растру |
| ✕ | удалить выбранный эталон |
| **class:** | атрибут с классом объекта |
| **key:** | атрибут, служащий ключом объекта |
| 1 / 2 / 3 / not set | проставить типичность выделенного объекта вручную |
| ⤓ to field | дублировать оценки в атрибут слоя |
| ⚙ Auto-assess | оценить один объект с разбором каждой метрики и её вклада |
| ⚙ Batch over layer | оценить все объекты, у чьего класса есть эталон |
| ⬇ Import assessments | загрузить оценки обратно из JSON или CSV |
| ▦ Separability matrix | прогнать каждый объект по каждому эталону |

Оценки и эталоны живут в свойствах проекта, поэтому сохраняются вместе с `.qgz`
и не требуют редактируемого векторного слоя. В исходные данные ничего не
пишется, пока вы не попросите об этом галочкой **⤓ to field**.

### Дублирование оценок в атрибут

Хранение в проекте не трогает ваши данные, но и выносит оценки за пределы всего,
что QGIS умеет делать с атрибутами. Поставьте галочку **⤓ to field** — и они
дополнительно пишутся в настоящее целочисленное поле `typicality`: десять
символов, ровно столько, сколько допускает shapefile.

```
"typicality" = 3                          -- отобрать нетипичные
"typicality" IS NULL                      -- что ещё не оценено
```

Дальше поле ведёт себя как любое другое: категоризованный стиль, подписи,
*Выделить по выражению*, объединения, экспорт в любой формат.

- Включение сначала спрашивает, заводит поле, если его нет, и заполняет всем,
  что уже оценено.
- Дальше каждая оценка поддерживает поле в актуальном состоянии — ручная,
  одиночная, пакетная и импортированная.
- У неоценённого объекта будет NULL, а не ноль: устаревшее значение от прошлого
  прогона хуже пустой ячейки.
- Выключение лишь останавливает дальнейшую запись. Уже записанное в слое
  остаётся — удалять колонку, которую никто не просил удалять, было бы хуже.
- Если слой открыт на редактирование, правки попадают в ваш буфер и стек отмены,
  и момент сохранения выбираете вы. Иначе они сохраняются сразу.

Источник истины — по-прежнему проект, поле только его копия. Если они разошлись
— потому что галочка была снята или поле правили руками — снимите и поставьте её
снова: колонка перепишется из проекта целиком.

## Как устроена оценка

### Выборка пикселей

Контур объекта переводится в CRS растра, после чего окно выборки снапится к
пиксельной сетке. Это важно: если запросить у провайдера произвольный
прямоугольник, вернутся *пересчитанные* значения со сдвигом до полпикселя, а не
собственные пиксели снимка. Отбираются пиксели, **центр** которых лежит внутри
контура, — проверка по алгоритму чётно-нечётного пересечения лучом.

У всех каналов одна общая маска валидности, поэтому строка *i* полученной
матрицы — это один и тот же пиксель во всех каналах; без этого ковариация, SAM и
расстояние Махаланобиса не имели бы смысла. Окно читается полосами по 2 млн
пикселей, поэтому пик памяти держится в десятках мегабайт независимо от размера
объекта. Свыше 300 000 пикселей выборка равномерно прореживается, и этот факт
записывается в выгрузку.

### Эталон класса

По пикселям класса считаются вектор средних (спектральная сигнатура) и
ковариационная матрица. Выборочная ковариация вырождается, когда пикселей мало
относительно числа каналов, поэтому она всегда сжимается к масштабированной
единичной матрице:

    Σ′ = (1 − λ)·Σ + λ·(tr Σ / k)·I,    λ = min(1, k / n)

Коэффициент сжатия λ сохраняется в профиле: чем он выше, тем меньше доверия
ковариации, и при больших значениях панель предупреждает об этом.

### Метрики

Каждая метрика возвращает «сырое» значение в своих единицах и похожесть в [0, 1].

| Метрика | Что измеряет | Приведение к шкале |
|---|---|---|
| Спектральный угол (SAM) | угол между векторами средних | `exp(−α / 0,15)` |
| Махаланобис | отклонение среднего объекта от эталона | p-value χ² с k ст. св. |
| SAM попиксельно | доля пикселей в пределах 0,10 рад от сигнатуры | сама доля |
| Доля «своих» пикселей | доля пикселей внутри 95 % эллипсоида | сама доля |
| Джеффриса–Матусита | разделимость двух распределений | `1 − JM / 2` |
| Пересечение гистограмм | поканальное перекрытие на сетке эталона | само перекрытие |

Все шесть считаются всегда, но у последних двух вес по умолчанию нулевой: они
показываются для интерпретации, а вес им можно задать в диалоге. Четыре
остальные делят вес поровну, по две на группу.

Два решения стоит объяснить отдельно:

- **SAM приводится к шкале экспоненциально, а не линейно.** Реальные углы между
  классами наземного покрова лежат в пределах 0,02–0,3 рад, поэтому линейная
  шкала `1 − α/(π/2)` давала бы 0,98 для любой пары и ничего не различала.
  `exp(−α/0,15)` даёт 0,5 при 0,10 рад — привычный порог «тот же класс» в
  дистанционном зондировании.
- **Махаланобис считается относительно разброса класса, а не стандартной ошибки
  среднего.** При тысячах пикселей вторая загнала бы p-value в ноль для любого
  объекта. Здесь задаётся другой вопрос: «правдоподобно ли, что объект — ещё одна
  реализация этого класса», а не «различимы ли средние статистически».

### Вердикт

Похожести сводятся в один score. Веса делятся поровну между двумя видами
свидетельств — метриками по среднему спектру и метриками по отдельным пикселям,
— чтобы две коррелированные метрики по среднему не перевесили попиксельные и
неоднородный объект не прошёл как типичный.

    score = Σ wᵢ·simᵢ / Σ wᵢ                    (сумма, по умолчанию)
    score = exp(Σ wᵢ·ln simᵢ / Σ wᵢ)            (произведение, строже)

Метрика, которую не удалось посчитать, исключается с пометкой, а её вес
перераспределяется; молча ничего не додумывается. Score превращается в вердикт:
`≥ 0,66` — это 1, `≥ 0,33` — 2, иначе 3. Веса, пороги и способ свёртки
настраиваются в окне автоопределения и запоминаются между запусками; пакетный
прогон берёт то, что выставлено там.

## Что получается на выходе

**JSON (v2)** — запись на каждый объект: атрибуты, центроид, контур в CRS растра
(кольцами и в WKT), поканальная статистика внутри объекта и в фоне, вектор
средних и ковариация, оценка типичности. Средние и ковариация лежат там для
того, чтобы метрики можно было пересчитать вне QGIS. Объекты без пикселей не
выбрасываются, а помечаются `n_pixels: 0`, чтобы выгрузка оставалась полной
копией слоя.

**CSV пакетного прогона** — строка на объект: score, вердикт и по каждой метрике
её сырое значение, похожесть и вес. Пишется в UTF-8 с BOM и разделителем `;`,
чтобы русский Excel открыл файл без плясок с кодировкой. В pandas:
`pd.read_csv(path, sep=';')`.

**Матрица разделимости** — два файла: подробный (строка на объект, колонка на
эталон) и сводка с медианой score по парам «класс объектов × эталон» и долей
объектов, у которых свой эталон оказался лучшим. Если класс не выигрывает сам у
себя, проблема в его эталоне или в контурах, а не в объектах.

И JSON, и CSV пакетного прогона читаются обратно кнопкой **⬇ Import
assessments**. Импорт откажется работать, если ключи из файла не совпали ни с
одним объектом слоя, и подскажет, какому полю они похожи.

## Разработка

Тесты покрывают чистую логику — метрики, профили, библиотеку, пакетный прогон и
разбиение на бины — и не требуют QGIS, только `numpy`:

```bash
python -m unittest discover -s test -t .
```

В Windows запускайте их питоном из поставки QGIS (`OSGeo4W Shell`) либо любым
питоном, где установлен numpy.

Устройство плагина:

| Путь | Что там |
|---|---|
| `calc_sp_ch.py` | контроллер: связь с QGIS, диалоги, действия |
| `calc_sp_ch_dockwidget.py` | панель и её сигналы |
| `raster_utils/` | выборка растра, привязка к сетке, гистограммы, маска-оверлей |
| `typicality/` | метрики, профили, библиотека, хранилище, пакет, диалоги |
| `export_json.py` | выгрузка и загрузка JSON v2 |
| `vector_utils.py` | перепроекция геометрии и работа с категоризованным стилем |
| `test/` | тесты |

`typicality/` и `raster_utils/histogram.py` намеренно ничего не импортируют из
QGIS — именно это и позволяет их тестировать.

### Переводы

Интерфейс на английском. Загрузчик ищет файл `i18n/calc_sp_ch_<locale>.qm`,
поэтому перевод можно добавить, не трогая код: извлеките строки через
`pylupdate5`, переведите `.ts` в Qt Linguist, скомпилируйте `lrelease` и
положите `.qm` в `i18n/`.
